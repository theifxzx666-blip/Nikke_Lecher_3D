# 莱彻 3D 查看器 · NIKKE 47/48 章关底 BOSS

两个关底 BOSS（安尼希利奥 / 莉贝雷利奥躯体）的 1·2 阶段 3D 模型，
从客户端资源包直接导出，**带骨骼、关卡内 idle 与全部登场 / 转阶段 / 战败表演动画**。
可在浏览器里旋转、切阶段、逐部件拆解、逐条播动画，并能一键导出 GIF 动图。

- 在线地址：<https://theifxzx666-blip.github.io/Nikke_Lecher_3D/>
- 参考站 nkas 的同类页面用的是静态烘焙网格（`skins=0 / animations=0`），
  网页里「动」只是 OrbitControls；本项目的模型是真的在播骨骼动画。

## 操作

| 操作 | 说明 |
|---|---|
| 左键拖动 / 滚轮 / 右键拖动 | 旋转 / 缩放 / 平移 |
| 双击画面 | 复位视角 |
| BOSS / 阶段 | 四个形态的关卡内 idle 切换 |
| **表演动画** | 登场 / 转阶段（看破·循环·恢复）/ 战败，逐条播 |
| 播放 | 播 glb 内置骨骼动画，可调速 |
| 自动旋转 / 线框 / 深浅底 | 显示选项 |
| 部件 | 逐个勾选显隐，用来拆结构 |
| 截图 | 当前视角存 PNG |
| **导出 GIF 动图** | 长边 640 / 900 / 1200，帧率 12 / 15 / 20，深浅底可选 |

URL 参数：

```
?boss=xba003|eba002&phase=1|2&play=1&t=1.2&rot=1&wire=1&bg=light&ui=0
?glb=xba003_2phase_death.glb&title=安尼希利奥_2阶段_战败&play=0&ui=0
```

点过「表演动画」后再点 BOSS / 阶段按钮会退出点名模式，回到四个 idle 形态。

## 模型怎么来的

`export_glb.py` 从 `SkinnedMeshRenderer` + `MeshHandler` 取顶点/UV/三角形/蒙皮权重，
骨骼层级与绑定姿态来自 `Transform` 树与 `m_BindPose`，动画取 `AnimationClip` 的
generic TRS 曲线逐帧采样成 glTF animation channel，贴图按内容 sha1 去重。

踩过的坑都记在项目文档里，最要命的几条：

1. **阶段归属要按变体根判定**。包里 1/2 阶段是两套并列的 `*_1phase_var` / `*_2phase_var`，
   都 `activeInHierarchy=True`。按「最近一个名字带 1phase/2phase 的节点」判会把
   `xba003_1phase_magiccarpet_skin`（名字带 1phase、实际挂在 2phase_var 下）算进 1 阶段。
2. **子网格必须逐块配材质**。`Mesh.m_SubMeshes` 与 `Renderer.m_Materials` 按下标一一对应；
   只取 `m_Materials[0]` 会让 78% 的几何贴上错误图集，表现就是「碎、丢细节」。
3. **IBM 就是 `m_BindPose` 本身**，不要再求逆；朝向修正要左右各乘一次
   （顶点 `A·V`、IBM `A·bindPose·A`，`A = diag(-1,1,-1)`）。
4. **动画绑哪套骨架 ≠ 包名写的阶段**。`anim_eba002_2phase_intro_01` 的 338 个唯一骨骼路径
   **全部命中 `eba002_1phaseAvatar`**；`anim_xba003_12phase_appeanrance`（包名自己就拼错）
   也只绑 1 阶段骨架。按包名取会导出 0 条通道的静态模型，而且不报错。
   导出时加了断言：命中数 `n_hit == 0` 或「路径 ≥ 20 条却命中不到 15%」直接抛错。

## 取景：为什么需要 `framing.js`

有些表演动画会把模型**整体搬走很远**（莉贝雷利奥战败时环状部件炸开到几百单位外）。
按绑定姿态或按整段包围盒取景都会出事：

- 用绑定姿态框 → 后段模型跑出画面，导出 GIF 全是背景，直接报「采样到的颜色太少」；
- 用整段动画的 min/max 并集 → 包围盒被碎屑撑到绑定姿态的 **29 倍**，主体缩成一个点。

`framing.js` 是离线算好的取景表：用 numpy 复算 LBS 蒙皮，逐帧取
**稳健**包围盒（中心 = 顶点分量中位数，半径 = 92 分位距离 ×2），分两种用法：

| 场景 | 用哪份数据 |
|---|---|
| 交互查看 | `union`：整段动画的并集框，可自由转视角 |
| GIF 导出 | `track`：逐帧跟**中心**，但**整段共用一个距离**，半径上限「绑定姿态 × 3」 |

为什么 GIF 不逐帧各算距离：试过，镜头会忽近忽远 —— 安尼希利奥登场前两帧被上下裁掉、
后两帧缩成一小块。上限那 3 倍是留给主体的，飞散的碎屑允许出画。

顺带纠正一条曾被写进文档的错误结论：这些大位移**不是**取景问题之外的通道 bug，
而是动画内容本身（环状部件炸开 / 整具下落）。早期试过「元凶通道减去自身首帧值」，
实测与「什么都不做」的包络逐条相同 —— 那些通道首帧值本来就是 0，减 0 等于没减。

## GIF 导出的四个约束

- 逐帧定格必须走 `canvas.toDataURL`，不能用 `Page.captureScreenshot` —— 后者是异步合成器
  出图，连拍会差一帧。
- 裁剪要用 `framing.js` 的 `track`，不要用整段并集（理由见上一节）。
- `AnimationAction.paused = true` 会把 `timeScale` 归零，`mixer.setTime()` 推不动时间轴；
  顺序必须是 `paused=false → setTime() → paused=true`。
- 调色板采样不能太稀。战败动画「边散架边缩小」，采样到非背景像素的概率极低，
  按 `perFrame` 算出的步长会跳过全部有效像素，报「采样到的颜色太少，无法生成调色板」。
  现在采样上限取 12 帧，且稀疏采样拿不到点时做一次稠密重扫。

另外 GIF 的帧延迟以 **10 ms** 为单位，写 79 ms 会存成 70 ms。按目标帧率硬算 duration
会让 4.77 s 的动画播成 4.20 s（快 11%），所以导出的帧数与间隔是反解出来的：
在 10 ms 网格上找 `n × ms` 最贴近原时长、且最接近目标帧率的组合，误差现在都在 0.3% 以内。

画质上用了 2× 超采样（渲染 2 倍分辨率再降采样到目标尺寸），小尺寸不会糊。

## 本地运行

浏览器的跨域限制会让 `file://` 下的 `.glb` 加载失败，需要起一个静态服务：

```bash
python -m http.server 8765 --bind 127.0.0.1
# 然后打开 http://127.0.0.1:8765/index.html
```
